# Astra로 내 업무를 자동화하기

MOYI AI 자동화·바이브코딩 강의 확장 원고 | 2026-09-09

이 문서는 기존 94쪽 강의를 Astra 기준 106장으로 확장하는 데 사용한 교육 설계와 실습 원고다. 공개 슬라이드·PC 및 모바일 PDF·설문 학습 가이드와 함께 사용한다. 대상은 AI 질문 경험은 있지만 자신의 업무를 자동화하는 데 어려움을 겪는 직장인으로 가정했다. 기본 운영은 120분 입문 워크숍과 주 1회 90분의 4주 실습 과정이다.

## 1. 이번 개편의 목표

수강생이 끝날 때 다음 다섯 가지를 갖도록 구성한다.

1. 자동화할 업무 한 개와 그 업무의 현재 처리 시간.
2. 입력 자료, 처리 규칙, 사람의 판단 지점, 결과물, 완료 기준을 담은 업무 요청서.
3. 샘플 자료로 동작하는 첫 결과물.
4. 정상·누락·중복 상황을 확인한 검증표.
5. 다음 주 또는 새 Codex 작업에서 이어 쓸 인계문.

교육의 중심 질문은 “어떤 AI가 좋은가?”에서 “내 업무를 어디까지 맡겼으며, 무엇을 확인하면 완료인가?”로 확장한다. 모델 소개는 이 질문에 답하는 데 필요한 만큼만 배치한다.

## 2. 원본의 강점과 개편 위치

원본은 AI 기본 원리에서 프롬프트, API, 자동화 기획, 에이전트 운영, 실행 요청서로 이어지는 구조다. 전체 페이지의 시각적 구조를 확인했고, 컨텍스트·지속 기록·요청서·마지막 실습 페이지는 확대해 확인했다. 원본에 인용된 다른 기업 사례와 수치는 이번 작업에서 모두 재검증한 것은 아니므로 최신 사실처럼 새 강의에 그대로 재사용하지 않는다.

| 원본 위치 | 개편 방향 | 수강생에게 남길 것 |
|---|---|---|
| 1~10쪽: AI 이해·모델 차이 | 기초 원리는 압축하고 Astra, Codex, 연결 도구를 구분 | 모델과 작업 환경을 구분하는 한 문장 |
| 11~27쪽: 지시·자동화·검증 | 좋은 요청과 실패 조건을 같은 샘플 업무에 적용 | 업무 요청서와 예외 3개 |
| 28쪽: 컨텍스트 압축·새 세션 | `/compact`, CLI `/clear`, 새 작업, 인계문 실습 추가 | 언제 압축하고 언제 새로 시작하는지 판단 |
| 29~41쪽: 모델·제품·도구 실행 | Astra 기준의 핵심 동작과 계정별 도구 확인으로 재편 | 현재 사용할 수 있는 도구 목록 |
| 42~58쪽: 업무 흐름·효과·데이터 | 설문 관심 분야와 연결하고 성과 측정 실습 강화 | 자동화 후보와 도입 전후 측정표 |
| 59~61쪽: 지속되는 업무 기록 | 작업 규칙·결정·진행 상태를 나누어 저장하는 실습 | 인계 파일 |
| 62~74쪽: 에이전트·오케스트레이션 | 공통 강의에서는 단일 작업 흐름, 심화에서 역할 분담 | 입력→실행→검증→예외 처리 흐름 |
| 75~83쪽: 배포·UX·보안·용어 | 초보자에게 필요한 설명만 본문에, 상세 내용은 선택 부록 | 실행 환경과 공유 범위 확인 |
| 84~94쪽: 실전 프롬프트·마무리 | 사전 설문 답변으로 개인화하고 4주 스터디에 연결 | 내 과제 1개와 다음 행동 |

94장을 모두 120분 동안 설명하기보다 핵심 32장으로 진행하고, 원본의 기술 설명과 사례를 참고 자료로 연결하는 구성을 제안한다. 기존의 짧은 실행 시간·모델 순위·플랫폼 출시 정보는 시연 환경과 확인 날짜를 붙이거나 설명용 예시로 표시한다.

## 3. Astra를 쉽게 소개하는 강의 원고

### 강사가 읽을 설명

“Astra는 복잡한 내용을 이해하고 판단하는 모델입니다. Codex는 그 모델이 파일을 읽고, 코드를 고치고, 결과를 확인하며 일할 수 있게 해 주는 작업 환경입니다. 연결된 도구는 그 작업에서 쓰는 손과 발에 해당합니다. 같은 모델을 골라도 어떤 파일과 도구에 접근할 수 있는지에 따라 실제로 끝낼 수 있는 일이 달라집니다.”

공식 모델 문서는 GPT-6 Astra를 복잡한 추론, 코딩, 컴퓨터 사용, 연구, 문서 작성에 사용하는 모델로 설명한다. 교육에서는 이 가운데 ‘자료 이해→업무 설계→제작→검증’의 연결을 보여준다. 모델의 기능 지원이 현재 수강생 계정에서 모든 도구를 사용할 수 있다는 뜻은 아니다. [Astra 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)

### Astra와 일하는 요청법

“목적은 분명하게, 사소한 결정은 맡기고, 결과를 바꾸는 결정은 확인하게 합니다.”

수강생에게 매 단계 클릭 방법을 길게 지시하도록 가르치기보다, 입력·결과·허용 범위·검증 기준을 먼저 정하도록 한다. Astra 공식 가이드는 자율적인 완료, 지시 파일의 충돌 관리, 필요한 수준의 테스트, 명시적인 하위 작업 지시를 다룬다. 아래 예문은 이를 교육 상황에 맞게 새로 작성한 것이다. [Astra 사용 가이드](https://developers.openai.com/api/docs/guides/latest-model)

```text
목표는 샘플 주문 파일을 정리해 검토 가능한 결과 파일을 만드는 것이다.
먼저 제공한 자료를 확인하고, 목표 달성에 필요한 작업을 끝까지 진행해줘.
파일 이름과 표 정렬처럼 되돌릴 수 있는 세부사항은 합리적으로 정하고 알려줘.
금액 계산 기준처럼 결과를 크게 바꾸는 정보가 빠졌으면 해당 항목만 질문해줘.
결과 파일을 다시 열어 입력 건수, 합계, 제외된 행을 검증해줘.
완료한 것과 실제로 확인하지 못한 것을 구분해 보고해줘.
```

### 추론 강도는 어떻게 설명할까?

추론 강도는 ‘어려운 문제를 풀 때 어느 정도 생각하도록 설정할지’다. 강도만 올리면 정확성이 보장되는 것은 아니다. 샘플 실습은 화면에 제공되는 기본 설정으로 시작하고, 여러 규칙이 충돌하는 설계나 원인 분석에서 더 높은 강도를 비교해 본다. 모든 실습을 가장 높은 설정으로 고정하지 않는다.

API 문서의 옵션 이름·가격과 Codex 앱에 표시되는 설정·사용량은 구분한다. 수강생에게는 자신이 사용하는 화면의 모델 선택기와 `/status`를 확인하게 한다. 강의에서 정확한 사용량 절감률이나 속도 향상률을 보장하지 않는다.

## 4. 스터디 설문을 강의의 시작점으로 연결

### 실제 페이지에서 확인한 내용

[나에게 필요한 AI 스터디 찾기](https://office-ai-prompt-builder.nenovabusiness1.chatgpt.site/study-survey)는 이름/닉네임, 선택 연락처와 함께 아래 8개 항목을 묻는다.

| 설문 항목 | 강의에서 활용하는 방법 |
|---|---|
| AI 사용 수준 | 처음 사용할 때 필요한 안내량 조절 |
| 사용 중인 LLM·AI 도구 | 수강생별 접속·도구 준비 확인 |
| 사용 기간 | 경험 참고 자료로 활용 |
| 관심 분야 | 실습 소재 선택 |
| 스터디 목표 | 결과물 형태 선택 |
| 실제 만들고 싶은 것 | 개인 프로젝트 초안 작성 |
| 가능한 시간 | 과제 크기 조절 |
| 가장 어려운 점 | 피드백 방식 조절 |

관심 분야는 프로젝트 관리, 반복업무 자동화, 바이브코딩, 영상 제작, 문서·보고서, 데이터 분석, 이미지 제작, 개인 목표 관리다. 페이지에는 학습 방향, 먼저 해볼 것, 4주 계획과 준비 항목이 표시되며, 응답 저장 동의를 포함한 별도 제출 영역이 있다.

확인한 기본 화면에서는 ‘기초·반복업무 자동화’ 방향과 사례 분석 15분+직접 제작 60분+피드백 15분이 표시되었다. 이는 화면의 초기 선택에 따른 출력이며, 실제 참여자들의 설문 응답이나 수요 집계로 해석하지 않는다. 다른 모든 선택 조합의 추천 동작까지 검증한 것은 아니다.

### 새로 제안하는 교육 연결 방식

설문을 점수 경쟁이나 고정적인 능력 판정에 사용하지 않는다. 관심과 준비 상태에 따라 시작 과제를 정하고, 10분 실습 결과를 보고 과제 난도를 조정한다. 사용 기간이 길다는 이유만으로 고급 과제를 배정하지 않는다.

| 주된 관심 | 첫 실습 결과물 | 검증 기준 예시 |
|---|---|---|
| 문서·보고서 | 회의 기록에서 실행 항목 표 만들기 | 담당자·기한을 임의로 만들지 않음 |
| 반복업무 자동화 | 주문 CSV 정리 파일 | 누락·중복·합계 검증 |
| 데이터 분석 | 주간 집계와 설명 | 기간·분모·합계 일치 |
| 바이브코딩 | 입력→검토→완료가 보이는 작은 웹 화면 | 빈 입력·중복·실패 상태 처리 |
| 프로젝트 관리·개인 목표 | 실행 항목과 다음 행동 목록 | 담당·기한·완료 기준 명확화 |
| 이미지·영상 | 제작 명세와 첫 시안 | 요구한 비율·문구·장면 반영 확인 |

이미지·영상 생성은 실제 연결된 제작 도구가 있을 때 실습한다. Astra 자체가 모든 형식의 미디어를 직접 출력한다고 설명하지 않는다.

가장 어려운 점에 따른 지도 방식도 다르게 한다.

- 무엇을 질문할지 모름: 업무를 5줄로 쓰고 요청서로 바꾸기.
- 결과가 매번 다름: 고정 샘플, 출력 양식, 판정 기준 만들기.
- 업무 적용이 어려움: 실제 업무 한 건을 입력→검토→출력으로 나누기.
- 코딩·도구 연결이 어려움: 파일 한 개를 처리하는 로컬 실습부터 시작.
- 꾸준히 사용하지 못함: 주 1회 반복할 작은 과제와 진행 기록 만들기.

설문 자체를 향후 확장한다면 ‘샘플 자료 보유 여부’, ‘현재 처리 시간과 빈도’, ‘완료 예시’, ‘공유 가능한 자료 범위’ 네 항목을 제안한다. 현재 사이트에 이미 있는 문항과 이 제안 문항은 구분한다.

## 5. 120분 워크숍 구성

| 시간 | 내용 | 수강생 행동 |
|---|---|---|
| 0~10분 | 설문과 내 과제 선택 | 관심·목표·어려움 확인 |
| 10~25분 | Astra·Codex·도구의 관계 | 현재 사용 가능한 환경 확인 |
| 25~45분 | 업무 5줄→실행 요청서 | 샘플·규칙·완료 기준 작성 |
| 45~70분 | 첫 결과물 만들기 | 작은 입력으로 실행 |
| 70~90분 | 누락·중복·실패 검증 | 잘못된 입력으로 다시 확인 |
| 90~105분 | `/` 명령과 컨텍스트 관리 | 상태 확인·압축·인계 연습 |
| 105~115분 | 결과 공유와 수정 | 실제 결과·미확인 항목 구분 |
| 115~120분 | 4주 계획 연결 | 다음 주 과제 한 개 확정 |

### 핵심 32장 구성안

각 장은 하나의 결론과 하나의 예시만 본문에 두고, 긴 프롬프트는 배포 원고로 제공한다.

1. 오늘 완성할 것: 내 반복 업무를 설명하는 요청서와 첫 결과물.
2. 설문으로 내 출발점 확인하기.
3. 경험보다 중요한 것: 사용할 샘플 자료가 있는가.
4. 자동화 후보는 매번 비슷한 입력과 출력에서 찾기.
5. Astra는 판단을, Codex는 작업 환경을 제공한다.
6. 연결된 도구와 허용 범위를 확인하기.
7. AI에게 맡길 판단과 계산 규칙 구분하기.
8. 좋은 요청은 결과를 확인할 방법까지 포함한다.
9. 내 업무를 5줄로 적기.
10. 목적·사용자·필수 기능·기존 작업과의 관계·제외 범위·완료 조건.
11. Astra가 스스로 정해도 되는 것과 질문할 것.
12. 입력 파일 한 개로 시작하기.
13. 첫 실행: 주문 자료를 검토용 파일로 만들기.
14. 실행 과정을 읽는 법: 읽음·수정함·검증함.
15. 그럴듯한 보고와 실제 파일을 구분하기.
16. 정상 사례 한 개 확인하기.
17. 누락 값이 있으면 어떻게 처리할까.
18. 중복과 재실행은 어떻게 확인할까.
19. 오류를 전달할 때 기대 결과와 실제 결과를 함께 쓰기.
20. 수정 범위와 완료 기준을 다시 확인하기.
21. 컨텍스트는 현재 작업 책상에 펼쳐 놓은 자료.
22. `/status`: 책상과 사용량 상태 확인.
23. `/compact`: 핵심을 요약해 같은 일을 이어가기.
24. CLI `/clear`와 새 작업: 새 대화로 시작하기.
25. `/fork`: 지금까지의 내용을 가지고 다른 안을 탐색하기.
26. `/plan`, `/model`, `/reasoning`, `/review` 실전 사용.
27. 결정·파일·미완료를 인계문으로 남기기.
28. 새 작업에서 인계문으로 재개하기.
29. 효과 측정: 검토·재작업 시간도 포함하기.
30. 설문 관심 분야별 첫 프로젝트 선택.
31. 4주 동안 제작·검증·재사용하기.
32. 내 결과물, 다음 행동, 완료 기준 발표.

### C. 첫 제작: 샘플 주문 CSV 정리

```text
교육용 주문 CSV를 검토용 결과 파일로 만들어줘.
열은 주문번호, 주문일, 거래처, 품목, 수량, 단가다.

규칙:
- 원본은 보존하고 결과는 새 파일로 만든다.
- 필수 값 누락, 숫자가 아닌 수량·단가, 음수 값은 검토 대상으로 분리한다.
- 주문번호+품목이 같은 행은 중복 후보로 표시하고 자동 삭제하지 않는다.
- 유효 행의 금액은 수량×단가로 계산한다. 세금 계산은 이번 범위에서 제외한다.
- 총 입력 건수, 유효 건수, 검토 건수를 함께 표시한다.

완료 기준:
- 입력 모든 행의 처리 결과를 추적할 수 있다.
- 샘플의 기대 합계와 결과 합계가 일치한다.
- 결과 파일을 다시 열어 내용과 파일 경로를 확인한다.
- 같은 입력으로 다시 실행해 결과가 중복 누적되지 않는지 확인한다.

제공된 샘플부터 확인한 뒤 구현하고 검증해줘.
결과를 바꾸는 정보가 부족한 경우에만 해당 질문을 해줘.
```

강사는 최소 6행의 가상 자료를 준비한다. 정상 행 2개, 수량 누락 1개, 숫자 오류 1개, 중복 후보 2개를 넣는다. 어떤 행을 합계에 포함할지는 실습 전에 명시하며, 중복 후보의 포함 여부도 검토 규칙에 적는다. 학생들이 합계 기대값을 먼저 계산하도록 한다. 운영 주문·재고 자료를 바꾸는 실습으로 연결하지 않는다.

다음 작업의 시작 문장:

```text
CURRENT_TASK.md와 관련 결과 파일을 읽고 현재 상태를 확인해줘.
```

여기서 CURRENT_TASK.md는 강의에서 정한 파일 이름이다. 파일 이름만으로 자동으로 읽힌다고 가정하지 않고 새 작업에서 명시적으로 읽도록 요청한다.

## 7. Codex `/` 명령어 쉬운 안내

`/` 뒤에 쓰는 것은 대부분 약어가 아니라 영어 명령 이름이다. 채팅 입력창에 `/`를 입력하면 현재 환경에서 사용할 수 있는 목록을 확인할 수 있다. 앱·CLI·버전·권한에 따라 목록이 다르다. 아래는 2026-09-09 공식 문서 확인 기준이며, 수강생 화면에 나타나는 항목을 우선 사용한다.

### 가장 헷갈리는 세 가지

| 기능 | 쉽게 말하면 | 사용할 상황 |
|---|---|---|
| `/compact` | 긴 대화를 핵심 요약으로 접어 두기 | 같은 업무를 계속하는데 대화가 길어졌을 때 |
| `/clear` — CLI | 터미널 화면을 비우고 새 대화 시작 | 다른 주제로 새로 시작할 때 |
| 새 작업 / CLI `/new` | 새 대화 시작 | 업무별 대화를 분리할 때 |

`/compact`는 핵심을 남기지만 세부 내용이 빠질 수 있다. 중요한 계산 규칙과 결정은 파일에도 남긴다. `/clear`는 프로젝트 파일의 변경을 되돌리는 기능이 아니다. CLI의 `Ctrl+L`은 화면만 정리하고 대화는 유지한다. CLI `/new`는 새 대화를 시작하지만 `/clear`처럼 먼저 터미널 화면을 지우지 않는다. 데스크톱 공식 목록에는 `/clear`가 기재되어 있지 않으므로 앱에서도 반드시 된다고 가르치지 않는다. [CLI 명령 설명](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

컨텍스트와 사용량도 구분한다. 컨텍스트는 현재 답변을 만들 때 참고하는 작업 공간이다. 사용량 한도는 계정에서 사용할 수 있는 양이다. 압축이나 새 대화를 ‘사용량 충전’으로 설명하면 안 된다.

### 데스크톱에서 먼저 익힐 명령

| 명령 | 쉬운 뜻 | 예시 상황 |
|---|---|---|
| `/status` | 상태 보기 | 컨텍스트·사용량 확인 |
| `/model` | 모델 선택 | Astra 선택 가능 여부 확인 |
| `/reasoning` | 생각의 강도 선택 | 복잡한 설계 검토 |
| `/plan` | 계획 모드 전환 | 큰 작업 순서 정리 |
| `/compact` | 대화 압축 | 긴 작업 이어가기 |
| `/fork` | 대화 복사·분기 | 다른 접근 시도 |
| `/review` | 코드 변경 검토 | 수정 후 문제 찾기 |
| `/goal` | 지속 목표 설정 | 여러 단계의 완료 목표 추적 |
| `/side` | 임시 곁가지 대화 | 본작업 중 별도 질문 |
| `/mcp` | 연결 도구 상태 | 서버 연결 확인 |
| `/init` | AGENTS.md 초안 | 프로젝트 작업 규칙 작성 |
| `/fast` | 제공되는 빠른 처리 선택 | 해당 모델에서 제공될 때 |

추가로 `/project`는 프로젝트 선택, `/task`는 프로젝트 없는 대화, `/local`·`/cloud`는 실행 위치, `/worktree`는 별도 Git 작업공간을 선택한다. `/approve`는 자동 검토에서 거절된 동작의 1회 재시도 승인이다. [데스크톱 슬래시 명령](https://learn.chatgpt.com/docs/reference/slash-commands)

`/review`는 실무 결과물의 정확성을 보장하는 인증이 아니다. 주문표 합계나 보고서 사실관계는 별도 검증한다. `/fork`의 대화 분기와 파일 작업공간 분리는 구분하고, 같은 폴더에서 같은 파일을 동시에 수정하지 않도록 실습을 구성한다. `/goal`을 특정 시각의 예약 실행으로 설명하지 않는다.

### CLI 사용자가 추가로 알아둘 것

| 명령 | 쉬운 뜻 |
|---|---|
| `/resume` | 저장된 대화 이어가기 |
| `/diff` | 파일 변경 내용 보기 |
| `/permissions` | 실행 권한 설정 |
| `/skills` | 전문 작업 지침 선택 |
| `/ps` | 백그라운드 터미널 보기 |
| `/stop` | 백그라운드 터미널 중지 |
| `/exit` 또는 `/quit` | CLI 종료 |

CLI `/clean`은 `/stop`의 별칭이다. `/clear`와 혼동하지 않는다. [CLI 명령 설명](https://learn.chatgpt.com/docs/developer-commands?surface=cli)

### 10분 실습 진행법

1. 2분: `/`를 입력하고 자기 화면에서 제공되는 명령 확인.
2. 2분: `/status`를 열어 대화 정보·컨텍스트·사용량 구분.
3. 3분: 핵심 결정과 다음 행동을 인계 파일로 정리.
4. 3분: `/compact` 후 기존 목표와 규칙을 다시 확인하거나, 새 작업에서 인계 파일을 읽고 재개.

초보자에게 모든 명령을 암기시키지 않는다. 첫날은 상태 보기, 계획 세우기, 압축, 새 작업, 인계의 흐름을 익히는 데 집중한다.

## 8. 4주 스터디 실행안

설문 사이트의 4주 흐름인 좋은 질문→업무 적용→결과·예외 검토→반복 사용을 유지하면서, 매주 제출할 산출물을 더 구체화한다. 아래는 새로 제안한 커리큘럼이다.

| 주차 | 90분 진행 | 제출물 | 통과 기준 |
|---|---|---|---|
| 1주 | 사례 15분·요청서와 샘플 60분·피드백 15분 | 업무 요청서·샘플·현재 처리 시간 | 입력과 완료 기준을 다른 사람이 설명 가능 |
| 2주 | 실행 시연 15분·첫 제작 60분·피드백 15분 | 동작하는 첫 결과물 | 정상 사례를 직접 열어 확인 |
| 3주 | 실패 시연 15분·예외 검증 60분·피드백 15분 | 오류·누락·중복 검증표 | 문제 행이 조용히 사라지지 않음 |
| 4주 | 인계 사례 15분·재실행·정리 60분·발표 15분 | 재사용 프롬프트·실행 절차·인계문 | 새로운 샘플로 재실행하고 차이를 설명 |

시간이 주 60분이면 과제를 ‘파일 한 개·규칙 한 개·결과물 한 개’로 줄이고, 사례 10분+제작 40분+피드백 10분으로 운영한다. 격주 120분은 주차를 두 회차로 묶되 중간 개인 실습을 둔다. 혼자 실습+월 1회 피드백은 같은 제출물 목록을 비동기 체크리스트로 사용한다.

### 성과 기록

한 회의 순절감 시간 = 기존 처리 시간 - (AI 실행 시간 + 사람이 검토한 시간 + 재작업 시간).

예: 기존 40분, 실행 5분, 검토 10분, 재작업 5분이면 한 회 20분 절감이다. 이 숫자는 교육용 계산 예시이며 실제 도입 효과가 아니다. 초기 구축 시간과 유지보수 시간은 별도 기록해 반복 횟수와 함께 평가한다.

### 마지막 발표 양식

```text
내가 줄이려는 업무:
입력 자료와 결과물:
Astra에 맡긴 부분:
사람이 확인하는 부분:
직접 검증한 정상·예외 사례:
처리 시간과 검토 시간:
아직 해결되지 않은 것:
다음 실행 방법과 파일 위치:
```

## 9. 강사 준비와 후속 제작 범위

- 가상의 실습 자료와 정답을 먼저 준비한다.
- 수강생 환경에서 모델과 도구를 실제 선택할 수 있는지 확인한다.
- `/` 목록은 강의 당일 다시 확인한다.
- 설문 결과는 학습 계획에 활용하되 공개 화면의 기본 선택을 실제 수요로 집계하지 않는다.
- 원본의 기업 사례, 출시 시점, 성능 수치를 재사용할 경우 해당 원출처를 다시 확인한다.
- 수정한 강의 자료에는 사실 확인 날짜와 앱/CLI 구분을 표기한다.

실제 강의 순서와 페이지 번호는 공개 슬라이드 및 PDF를 기준으로 한다. 이 원고의 32장 구성은 120분 핵심 진행안이며, 전체 106장과 일대일로 대응하지 않는다.

## 10. Codex 최초 설정 가이드: 본 강의 전 준비 실습

사용자가 반복해서 설명하지 않아도 되도록 작업 규칙과 인계 기록을 먼저 만드는 30분 준비 실습을 추가한다. 상세 배포 자료는 같은 폴더의 `codex-first-setup-guideline-2026-09-09.md`다.

처음에는 `AGENTS.md`에 지속 규칙, `CURRENT_TASK.md`에 현재 상태를 적는다. 검증된 반복 절차는 `SKILL.md`로 만들고, 결정이 누적되면 `DECISIONS.md`를 분리한다. 모델 등 실제 실행 설정은 MD와 구분해 앱 설정 또는 `config.toml`에서 다룬다.

배포 가이드에는 기존 설정 보존을 포함한 최초 생성 요청, 복사 가능한 MD 양식, Skill 생성·호출·검증 예시, Astra 기본 모델 설정 예시, 효율 측정 방법을 포함했다. 이 파일들은 교육용 예시이며 현재 프로젝트의 실제 규칙을 변경한 것이 아니다.

### 추가 준비 슬라이드 6장

1. AGENTS.md는 업무 기본 수칙, Skill은 특정 업무의 설명서.
2. 처음에는 작업 규칙과 인계장 두 개부터 만들기.
3. 기존 파일을 확인한 뒤 내 업무에 맞는 MD 생성 요청하기.
4. 성공한 반복 업무 한 개를 Skill로 만들기.
5. MD의 지시와 실제 모델·권한 설정 구분하기.
6. 새 작업에서 재개해 보고 반복 설명·재작업이 줄었는지 측정하기.

이 6장은 기존 핵심 32장과 별도의 준비 모듈이다. 120분 본 강의에 단순 추가하지 않고 사전 30분 실습으로 제공한다. 4주 스터디에서는 1주차에 MD 설정, 2주차 제작 후 Skill 추출, 4주차 인계·재실행 확인에 연결한다.
